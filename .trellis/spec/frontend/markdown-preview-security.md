# Markdown Preview Security

> Executable security contract for every React Markdown surface that accepts file or session content.

## 1. Scope / Trigger

Apply this spec whenever code adds or changes a `ReactMarkdown` consumer, raw HTML support, a rehype/remark plugin, URL handling, code highlighting, or Mermaid rendering.

Treat `MarkdownPreview` file content and `SessionViewerModal` assistant messages as untrusted input. Raw HTML is supported only through the sanitized subset described below; a caller must not bypass this pipeline because content came from a local file or an AI session.

## 2. Signatures

The shared boundary lives in `src/utils/markdownSanitize.ts`:

```ts
import type { Options as SanitizeSchema } from 'rehype-sanitize';

export const MARKDOWN_LANGUAGE_CLASS_PATTERN: RegExp = /^language-[\w#+.-]+$/i;
export function createMarkdownSanitizeSchema(baseSchema: SanitizeSchema): SanitizeSchema;
export const MARKDOWN_SANITIZE_SCHEMA: SanitizeSchema;
```

Every raw-HTML Markdown consumer must import that exported schema and use this exact pipeline shape:

```tsx
<ReactMarkdown
  remarkPlugins={[remarkGfm]}
  rehypePlugins={[rehypeRaw, [rehypeSanitize, MARKDOWN_SANITIZE_SCHEMA]]}
>
  {content}
</ReactMarkdown>
```

There is no backend, Tauri command, or database contract for this boundary.

## 3. Contracts

1. `remarkGfm` preserves GFM tables, task lists, strikethrough, and related syntax.
2. `rehypeRaw` converts embedded HTML into HAST. **`rehypeSanitize` must immediately follow `rehypeRaw`**, with no plugin between them that can consume or expand untrusted raw nodes.
3. `MarkdownPreview.tsx` and `SessionViewerModal.tsx` must use the same `MARKDOWN_SANITIZE_SCHEMA`; do not copy or locally extend the schema in a component.
4. `createMarkdownSanitizeSchema(defaultSchema)` keeps the GitHub-style base allowlist and replaces the `code` class rule with `MARKDOWN_LANGUAGE_CLASS_PATTERN`. Thus the only custom source class allowance is a `code.className` token matching `language-*`; arbitrary source classes are removed. Built-in GFM classes already present in `defaultSchema` remain unchanged.
5. The source allowlist preserves `details`/`summary`, safe GFM nodes, local relative image paths, and fenced-code classes such as `language-mermaid`.
6. Source elements or properties that can execute or restyle content are not allowed: `script`, `iframe`, every `on*` event property, and `style`. URL properties must not accept `javascript:`, `vbscript:`, or `data:`; the current schema intentionally allows no `data:` protocol, which also blocks dangerous data URLs.
7. A relative image `src` survives sanitation. Only afterward may `MarkdownPreview` resolve it against `currentPath` and pass it through `convertFileSrc`; a component must never restore a URL attribute removed by the sanitizer.
8. Highlight and Mermaid DOM are trusted post-sanitize output generated by React components, not raw Markdown passthrough. `MarkdownPre` reads sanitized `language-*` metadata, then renders `HighlightedCodeBlock` or `MermaidBlock`. Highlight markup comes from `highlight.js` with escaped fallback text; Mermaid runs with `securityLevel: 'strict'`. Do not broaden the source schema to admit `hljs-*`, SVG, event, or style markup supplied by Markdown.

## 4. Validation & Error Matrix

Sanitation rejects unsafe input by removing nodes/properties; it does not surface a user-facing validation error.

| Untrusted input or condition | Required sanitized result | Post-sanitize behavior |
|---|---|---|
| `<script>...</script>` or `<iframe ...>` | Forbidden element is absent | No executable/embed DOM is mounted |
| Any `onclick`, `onerror`, or other `/^on/i` property | Property is absent | React prop spreading cannot restore it |
| Any source `style` property | Property is absent | Source cannot inject inline CSS |
| `href="javascript:..."` or `href="vbscript:..."` | `href` is absent; safe element text may remain | Click handlers receive no unsafe URL |
| `href`/`src` using `data:` (including `data:text/html`) | URL property is absent | No later resolver may re-add it |
| `![local](./assets/chart.png)` | `src` remains `./assets/chart.png` | File preview may resolve it after sanitation |
| GFM table/task list or raw `<details><summary>...` | Allowed structure remains; task input stays disabled | Existing Markdown UX remains available |
| `class="language-mermaid extra"` on `code` | `language-mermaid` remains; `extra` is removed | Mermaid dispatch still works without arbitrary classes |
| Arbitrary source `hljs-*`, SVG, event, or style markup | Source markup/property is removed | Highlight/Mermaid React components generate their own DOM after sanitation |
| Mermaid parser/render failure | No raw source HTML is reinserted | Show the render error and sanitized code fallback |

## 5. Good / Base / Bad Cases

- **Good:** GFM content includes a table and task list, `<details><summary>More</summary>...</details>`, `![diagram](./img/diagram.png)`, and a fenced `mermaid` block. All features survive, while the Mermaid/highlight presentation is generated after sanitation.
- **Base:** Plain headings, paragraphs, links, lists, and fenced code use the shared pipeline even when no raw HTML is present.
- **Bad:** Content contains `<script>`, `<iframe>`, inline events/styles, `javascript:`/`vbscript:` links, a dangerous `data:` image, or arbitrary classes. The unsafe nodes/properties must be absent rather than hidden with CSS or filtered only in click handlers.

## 6. Tests Required

`tests/markdownSanitize.test.cjs` (using the compiled shared utility) is the minimum security regression suite. Its processor must mirror production order: GFM -> raw HTML -> shared sanitize schema.

Required assertions:

1. No `script` or `iframe` element remains.
2. Across every element, no property matches `/^on/i` and no `style` property remains.
3. `javascript:` and `vbscript:` links retain no `href`; dangerous `data:` links/images retain no URL property.
4. A relative image keeps its exact `src` before component-level path conversion.
5. GFM table and checked task-list input survive; the input is both `checked` and `disabled`.
6. `details` and `summary` survive.
7. `language-mermaid` survives, while non-`language-*` code class tokens and arbitrary raw classes do not.
8. Both production consumers import `MARKDOWN_SANITIZE_SCHEMA` and keep `rehypeRaw` immediately followed by `rehypeSanitize`.
9. Component tests, when changing renderers, prove that highlight/Mermaid DOM is created from sanitized code text and that renderer failure never falls back to unsanitized HTML.

Run the focused regression after compiling `tsconfig.test.json`, and run the normal frontend test command before merging any pipeline/schema change.

## 7. Wrong vs Correct

### Wrong

```tsx
// Sanitizes before raw HTML is expanded, then uses a component-local schema.
const localSchema = { ...defaultSchema, attributes: { '*': ['className', 'style'] } };

<ReactMarkdown
  rehypePlugins={[[rehypeSanitize, localSchema], rehypeRaw]}
>
  {content}
</ReactMarkdown>
```

This order can create raw nodes after the only sanitize pass, diverges between consumers, and admits source styling/classes.

### Correct

```tsx
import { MARKDOWN_SANITIZE_SCHEMA } from '../utils/markdownSanitize';

<ReactMarkdown
  remarkPlugins={[remarkGfm]}
  rehypePlugins={[rehypeRaw, [rehypeSanitize, MARKDOWN_SANITIZE_SCHEMA]]}
  components={{ pre: MarkdownPre }}
>
  {content}
</ReactMarkdown>
```

Sanitize immediately after raw parsing; let React components create highlight/Mermaid DOM only from the sanitized tree.
